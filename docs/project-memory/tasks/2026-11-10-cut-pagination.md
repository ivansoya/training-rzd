# 2026-11-10 — страницы роликов и кадров по 50

Запрос: убрать сплошной вывод роликов в таске нарезки, ограничить ролики и отображаемые кадры до 50.

Дополнение 2026-11-10: изменения оформлены коммитом `03d2a17` поверх коммита галереи `3fe6913`; код успешно выложен на VORAN-01. Push в GitHub не выполнялся. [Подробности выкладки](2026-11-10-release-voran.md). Ниже — результаты исходной задачи до публикации.

## Результат

- В `Sources.tsx` группы «Нарезанные» и «Ненарезанные» имеют независимую пагинацию по 50 роликов с существующим компонентом `Pager`. Только строки текущей страницы монтируются и загружают VideoStrip-превью. Фильтры применяются ко всему списку; их смена возвращает на первую страницу. Уменьшение списка ограничивает номер последней существующей страницей.
- Массовые действия агента и таги по-прежнему относятся ко всей отфильтрованной группе, а не только к текущим 50 роликам. Общие счётчики не урезаны.
- `CutFrames.tsx`: вместо двух накопительных списков по 24 кадра — один серверный запрос с `limit=50` и `offset` для всей галереи. Не более 50 кадров суммарно в секциях «Не размечены»/«Размечены». То же поведение у галереи одного ролика. Старые страницы заменяются, не накапливаются. Отмена устаревших запросов и повтор после ошибки сохранены.
- Фильтры состояния, тагов и ролика возвращают галерею на первую страницу; сворачивание сохраняет её номер и вид. Если после обновления страница исчезла, галерея запрашивает последнюю существующую.
- `backend/datasets_svc/task_routes.py`: добавлен `review=all` без брака и поле ответа `review_counts: {new, done}`. Счётчики учитывают source/tags/status/image до выбора review=new/done и не зависят от limit/offset. Старые запросы без review сохраняют семантику и получают null в review_counts. Типы контракта обновлены в `frontend/src/auth/api.ts`. Миграций нет.
- В `.most/run.json` созданы задачи локальной сборки, тестов логики, изолированного Vite и браузерных проверок. До задачи файла не было.
